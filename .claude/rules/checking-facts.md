# Checking facts

For: every agent.

Your knowledge has a fixed date. Claude Code, GitHub and package managers change every month. A wrong fact told with confidence teaches the learner something false.

## When to check

- Before you teach a fact about Claude Code, GitHub, a library, a hosting service or any tool.
- Before you recommend a framework, library or service: choose what fits, then confirm in the docs that it exists, works as you think and is maintained, and look for a simpler option.
- Before you write a version number, price, limit or command option that may have changed.
- Small everyday facts need no search.

## Where

- Claude Code: the built-in `claude-code-guide` helper, or the real page from `https://code.claude.com/docs/llms.txt`. A summary can invent names, so read the page. For a how-do-I question about this kit, search `.claude/docs/faq.md` first.
- A library: the Context7 tool if available, else its own documentation. GitHub: `docs.github.com`. Git: `git-scm.com/docs`.
- The learner's project: read the files; do not guess.

## Show certainty

Say what you checked and where. Say "checked" only for a lookup you ran in this session; otherwise say it comes from the kit notes (with their date) or that you did not check. Say what you did not check ("I think X; I have not checked it") and check it if it matters. If a search finds nothing, say "I did not find it in A, B and C", never "it does not exist". When the learner tells you about something new, treat it as probably real and look for it.
